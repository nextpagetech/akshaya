> Compact Home-page source of truth for Akshaya Enterprises / Akshaya Floor Solutions.
> Read this file together with `DESIGN_RULES.md` for Home-page tasks.
> Do not reread `PROJECT_CONTEXT.md` unless business/content validation is specifically required.

## 1. Home Page Goal
The Home page must help visitors understand:
1. what Akshaya does,
2. whether Akshaya understands their flooring problem,
3. whether Akshaya works with environments like theirs,
4. whether the company has technical capability,
5. whether execution is professional,
6. whether there is proof,
7. how to arrange a technical site visit.

Primary CTA:
**Schedule Site Visit**

## 6. What Problem Are You Facing?
Purpose:
Let visitors start from the floor problem rather than technical terminology.

Final concept:
# Interactive Floor Diagnostic

Not a card grid.

Desktop:
LEFT: problem selector  
RIGHT: 3D/isometric diagnostic floor

Problems:
- Floor Cracking
- Dust Generation
- Peeling / Damaged Coating
- Static Control
- Hygiene Requirement
- Water Penetration
- optional Heavy Traffic Wear
- optional Chemical Damage

Each problem visually changes the floor.

Examples:
- Cracking: animated crack path
- Dust: worn surface / subtle particles
- Peeling: lifted coating layer
- Static: technical static/grounding visual
- Hygiene: clean seamless surface
- Water: moisture spread / inspection zone

Dynamic panel:
- what it may indicate
- possible next steps
- possible solution categories
- disclaimer
- Schedule Assessment CTA

Mobile:
horizontal problem selector + floor visual + panel.

No rectangular problem-card grid.

compact isometric scene + outcome selector + explanation.

- System Selection: exploded system layers
- Application: flooring layer applied

## 18. Interaction Metaphors
Each important section must feel different.

- Hero: 3D brand/industrial scene
- Problem: diagnosis
- Solutions: system transformation
- Industries: environment explorer
- Why Akshaya: operational floor scene
- Technical Assessment: analysis lab
- How We Work: floor transformation journey
- Projects: case-study storytelling
- Post-Care: support/maintenance visual

Do not reuse the same card interaction everywhere.

## 19. Motion Principles
Use coordinated but section-specific motion.

- Confidence Ribbon: staggered capability reveal
- Problem: floor state transition
- Solutions: floor transformation + exploded layers
- Industries: image/content crossfade
- Operational Floor: zone illumination
- Technical Assessment: stage-specific technical visuals
- How We Work: scroll stage progression
- Projects: mask reveal
- Testimonials: crossfade
- Post-Care: support-state highlight

4. Quality / EHS / Compliance Manager

## 21. Content Rules
Do not invent:
- certifications
- customer logos
- warranty duration
- exact technical values
- project facts
- compliance claims
- confirmed suitability

Use safe wording where needed:
> Final system selection depends on site conditions and technical assessment.

## 22. Home Page Acceptance Standard
The Home page is ready only when:
- Hero is visually strong.
- Confidence Ribbon feels premium.
- Problem Finder is interactive and diagnostic.
- Flooring Solutions behaves like a system explorer.
- Industries feels immersive.
- Why Akshaya uses a visual operational metaphor.
- Technical Assessment visually changes the floor state.
- How We Work shows the floor transforming through execution.
- Projects feel like case studies.
- Testimonials feel editorial.
- Post-Care visually communicates support.
- Mobile is intentionally designed.
- No major section relies primarily on old-style repeated cards.
